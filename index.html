Scene Light Manager

A professional, modular Blender extension designed to optimize lighting workflows. Manage scene hierarchies, collection-level overrides, interactive viewport gizmos, and GPU shader previews from a single unified panel.

── 1. Architectural Design & Folder Layout ──

SLM is built under a modular design philosophy that separates Blender's registration lifecycle from UI layouts, operator actions, and custom data schemas. 

k_tools_scene_light_manager/
├── __init__.py               # Registers/unregisters core modules & registers subclasses
├── auto_load.py              # Handles dynamic recursive module detection and registration
├── blender_manifest.toml     # Metadata and platform information for Blender Extensions
├── preferences.py            # Global addon preferences, properties, and the main preference panel
│
├── properties/               # Persistent data and RNA properties
│   ├── outliner.py           # Custom attributes for outliner synchronization
│   └── light_properties.py   # Scene-wide properties and custom data types
│
├── operators/                # Logic and actions triggered by UI or viewport events
│   ├── assets.py             # Operations for importing library assets (Blockers, Bouncers)
│   ├── presets.py            # Rig generator operators (3-Point, Warm-Cool, Butterfly, etc.)
│   └── linking.py            # Collection and lighting relationship assignment handlers
│
├── ui/                       # Visual layout and draw calls
│   ├── main_panel.py         # Main N-Panel sidebar containing light lists and linking panels
│   ├── properties_light.py   # Preview generation buttons and object lighting adjustments
│   └── menu_popup.py         # Floating quick-popup settings panel
│
└── utils/                    # Shared helper functions and rendering controllers
    ├── addon.py              # Preference retrieval helpers
    ├── icons.py              # Dynamic preview and icon cache management
    ├── detection.py          # Background handler for light-groups and mesh lights
    └── viewport_preview.py   # GPU rendering drawing handles and depsgraph updates

── 2. Core Systems & Workflows ──

1. Viewport Gizmo Interface Provides direct interactive controls drawn right next to selected lights. Instantly adjust light type, Area shapes (Square/Disk/Rectangle/Ellipse), Solo status, sizes, and beam spreads without having properties tabs open.
2. GPU Linking Highlights System Utilizes Blender's GPU module shader pipelines (GPUShader) to render receiver/blocker outlines directly onto the viewport buffer during active Light/Shadow linking actions, avoiding undo stack bloat.
3. Interactive Sky Rotation A modal viewport operator that rotates world environment mapping coordinates, Nishita Sun angles, or viewport HDRI values. Triggered via Ctrl + Alt + RMB and dragged horizontally.
4. Geographic Sun & Sky Accepts decimal coordinates, Degree-Minute-Second DMS coordinates, or text-labeled maps to calibrate day/night cycles. Renders daily solar arc indicators and ground-horizon compass guides in the viewport.

── 3. Preview Rendering & Caching ──

To eliminate viewport stuttering and freezes when adjusting material properties, SLM implements three optimization structures:

  • Persistent Preview Scene Caching: A hidden scene (.slm_preview_scene) is kept alive containing camera, plane, and material blocks. Modifying shader nodes updates the material node tree but reuses the graphics pipeline, reducing render compiled times from ~200ms to ~10ms.
  • Depsgraph Update Debouncing: Dragging exposure or color sliders registers timestamp offsets. The render routine waits for a 0.4-second debounce window before triggering a redraw task, locking viewport navigation at a smooth 60 FPS.
  • Selection Isolation: Selecting an alternate light triggers instantly. The UI fetches existing thumbnails from cached storage immediately, delaying background renders until properties are actively tweaked.

── 5. Developer API & RNA Custom Properties ──

For pipeline integration, script automations, or asset exporters, SLM registers custom RNA data blocks:

Custom Collection Attributes

  • coll.k_tools_rig_type - Enum indicating spawned rig presets (3Point, Studio Duo, W-Cool, Rim, etc).
  • coll.k_tools_lock_exposure - Boolean toggle enabling exposure override.
  • coll.k_tools_lock_exposure_val - Float value (-10.0 to 10.0) driving exposure levels.
  • coll.k_tools_lock_lg_val - String setting target Light Group overrides.
  • coll.k_tools_lock_ll_val - Pointer property referencing Light Linking target collections.

Object State Caching Properties

  • obj["k_tools_original_exposure"] - Float storing pre-override exposure value.
  • obj["k_tools_original_lg"] - String storing pre-override Light Group assignments.
  • obj["k_tools_original_ll"] - Pointer mapping pre-override Light Linking paths.

── 6. Troubleshooting & FAQ ──

[WARNING] Viewport lag during slider manipulation: If adjusting exposure or colors causes micro-stuttering, ensure Cycles GPU is set as the active Preview Render Engine in Addon Preferences. Cycles performs asynchronous background renders, whereas EEVEE compiles shaders synchronously on Blender's main thread, causing frames to drop.

  • Q: Why is "No Shader Preview Rendered" showing?

    Shader previews require node-based materials. Ensure that the active emitter has "Use Nodes" enabled under Blender's shading editor. Previews are not compiled for standard inputs.

  • Q: A tagged Mesh Light is missing from the Outliner list?

    Ensure the mesh material has an active Emissive shader, and the mesh name or material name matches your preference keywords (e.g. glow, emit). You can also mark objects manually via the Mark as Mesh Light operator.
